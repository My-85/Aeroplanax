● 自动化训练框架操作指南

  整体工作流程

  训练 → 评估 → 达标？→ 是 → 结束，输出最终报告
                    ↓ 否
              Claude API 分析 → 生成代码补丁 → 应用补丁 → 回到训练

  ---
  一、环境准备

  1. 设置 API Key（Claude API 用于自动分析和优化）
  export ANTHROPIC_API_KEY="your-key-here"

  2. 确认 GPU 可用
  python -c "import jax; print(jax.devices())"

  3. 确认目标指标文件存在
  cat aircraft-rl-tuner/assets/target_metrics_template.json
  该文件定义了"什么叫训练达标"（成功率、崩溃率、失速步数等阈值）。

  ---
  二、基本用法

  最简启动（从头训练，最多跑10轮）

  cd /home/dqy/aeroplanax/new/20251215最新代码库
  python aircraft-rl-tuner/scripts/auto_train_loop.py

  常用参数

  python aircraft-rl-tuner/scripts/auto_train_loop.py \
      --max-iters 5 \            # 最多迭代5轮（默认10）
      --eval-episodes 100 \      # 每轮评估100个episode（默认50，越多越准但越慢）
      --target-metrics aircraft-rl-tuner/assets/target_metrics_template.json

  ---
  三、典型使用场景

  场景1：完全从头开始

  python aircraft-rl-tuner/scripts/auto_train_loop.py --max-iters 5
  第一轮从头训练 → 评估 → 不达标则 Claude 分析并打补丁 → 第二轮根据 Claude 建议决定续训或重训...

  场景2：已有 checkpoint，跳过首次训练

  python aircraft-rl-tuner/scripts/auto_train_loop.py \
      --checkpoint Planax/results/full_domain_maneuver_v3_xxx/checkpoints/checkpoint_epoch_1 \
      --max-iters 5
  直接用已有 checkpoint 评估，不达标则开始优化循环。

  场景3：只评估+优化，不实际训练（调试用）

  python aircraft-rl-tuner/scripts/auto_train_loop.py \
      --skip-training \
      --max-iters 1
  跳过训练，找到最新 checkpoint 直接评估，调用 Claude 分析。适合调试提示词或查看 Claude 给出的诊断。

  # 回滚到第2轮之前的状态
  cp aircraft-rl-tuner/assets/backups/iter_2/full_domain_reward.py \

  ---
  八、注意事项

  1. 首次运行必须从头训练：网络维度刚从 128 改到 256，旧 checkpoint 不兼容
  2. 训练时间较长：2e9 步在 A100 上可能需要 10+ 小时，整个循环（5轮）可能数天
  3. Claude API 费用：每轮调用一次 Claude Sonnet，上下文约 40K token，注意用量
  4. 安全机制：每次打补丁前都会自动备份到 backups/iter_N/，可随时回滚

    三、调用的是什么？是 Claude SDK 吗？                                                                                                      
                                                                                                                                            
  不是。 调用的是 Claude Code CLI（命令行工具），不是 Anthropic Python SDK。                                                                
                                                                                                                                            
  具体调用方式（auto_train_loop.py 第335-346行）：                                                                                          
                                                                                                                                            
  cmd = [                                                                                                                                   
      "claude", "-p",                      # 非交互 print 模式                                                                              
      "--dangerously-skip-permissions",     # 跳过权限确认                                                                                  
      "--no-session-persistence",           # 不保存会话                                                                                    
      "--model", "sonnet",                  # 用 Sonnet 模型                                                                                
      "--fallback-model", "haiku",          # Sonnet过载时降级为Haiku                                                                       
      "--max-budget-usd", "1.0",           # 单次调用最多花$1                                                                               
      "--tools", "",                        # 禁用所有工具（不让Claude自己Read/Edit）
      "--output-format", "json",           # 输出JSON格式
      "--json-schema", json_schema,        # 强制按schema输出
      "--effort", "low",                   # 低努力模式（快速响应）
  ]

  通过 subprocess.Popen 启动，prompt 通过 stdin 管道发送：
  proc = subprocess.Popen(cmd, stdin=subprocess.PIPE, stdout=subprocess.PIPE, ...)
  stdout_bytes, _ = proc.communicate(input=prompt.encode("utf-8"), timeout=1800)

  Claude被赋予的权限：无。 --tools "" 禁用了所有工具（Read/Edit/Bash），Claude 只能输出文本。代码修改是由 Python 端的 _apply_edits()
  函数执行的字符串替换，不是 Claude 直接修改文件。

  五、为什么调了半天没调出来？

  看 escalation_report.json 的3轮迭代历史：

  ┌───────┬────────────┬────────┬────────┬────────────────────────────────────────────────────────────┐
  │ 轮次  │ Checkpoint │ 坠机数 │ 成功率 │                       Claude做了什么                       │
  ├───────┼────────────┼────────┼────────┼────────────────────────────────────────────────────────────┤
  │ 第1轮 │ epoch_1000 │ 209.5  │ 0%     │ 降课程难度(heading 45→20°, pitch 15→8°)                    │
  ├───────┼────────────┼────────┼────────┼────────────────────────────────────────────────────────────┤
  │ 第2轮 │ epoch_1300 │ 42.0   │ 0%     │ 调奖励(close_bonus 1.0→0.2, full_bonus 3.0→4.0, Nz 12→16G) │
  ├───────┼────────────┼────────┼────────┼────────────────────────────────────────────────────────────┤
  │ 第3轮 │ epoch_1600 │ 47.0   │ 0%     │ 无修改记录(触发停滞检测)                                   │
  └───────┴────────────┴────────┴────────┴────────────────────────────────────────────────────────────┘

  3轮全部 0% 成功率，触发停滞检测 → NEEDS_CODE_REVIEW。

  根本问题分析：

  1. Claude 能力被严重限制：--tools "" + --effort low + --model sonnet，Claude 只能看到你喂给它的代码片段，不能自己读文件探索。对一个 820
  行的 env 文件，它只看到约 100 行关键段落，可能遗漏关键逻辑。
  2. 单轮分析深度不够：之前为了解决 API 超时问题，从多轮工具调用模式改成了单轮 JSON 模式。代价是 Claude 不能自己 Read 完整文件、不能 Grep
  搜索相关逻辑、不能迭代验证修改，只能根据 prompt 中嵌入的代码片段"盲猜"修改。
  3. 评估不充分：--eval-episodes 2（只跑 2 个 episode），统计样本太少，评估结果噪声巨大。209.5 次坠机 vs 42 次坠机可能只是随机波动。
  4. 训练量可能不够：每轮 3 亿步（epoch_1000 → 1300 → 1600，每轮加 300 epoch），对于一个 22D 观测 + 4
  通道离散动作的复杂控制任务，这可能远远不够。
  5. 参数调优治标不治本：Claude 每轮只做 3-5 个数值修改（调 bonus 系数、放宽阈值等），没有能力做结构性改动（如重设计 reward 组件、修改 obs
  space、修改网络结构）。而这个任务的 0% 成功率暗示问题可能是结构性的。
  6. param_registry.py 和 param_applier.py 完全没用上：这两个文件定义了 51 个可调参数及其安全范围，但 auto_train_loop.py 的 call_claude_code
   完全没有调用它们，而是让 Claude 直接输出代码补丁。
